为什么「第一次打开」一定是这个页面：启动管线是 drain_pending_open_paths（命令行/文件关联传入的路径）→ 没有就先读「最近打开」， 取首条恢复上一篇；两者都没有 → 保持 status: "empty"，于是渲染空态。 窗口以 visible: false 启动，等上面这条链跑完、再等两帧 requestAnimationFrame 才 show() —— 所以用户看到的第一帧就已经是最终画面，不会先闪一下空态再冒出文档。
也就是说：空态页里「最近打开」区块实际不会出现（它有记录时启动就直接恢复文档了；记录不可读时走的是错误态，那里才是这套列表真正登场的地方）。 想再看一次这一屏，删掉/清空最近打开记录即可（设置页「关于与数据」里有「清除」）。 外观：出厂 theme: "system"，跟随系统深浅；本页顶部两个按钮切的是同一套 [data-theme] 色板。 窄屏：窗口最小 520×420，< 720px 时 isNarrow 为真：侧栏转浮层 + 遮罩，空态与正文内距收窄到 24px 16px。
